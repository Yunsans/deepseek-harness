# 办公智能体自动评测插件

把《办公智能体评测_简化实用版》里的流程接到 DeepSeek Harness：用户先选择启用，再发任务，智能体答完后自动出题、抽查并逐项打勾。不打总分、不排名。

## 启动

在仓库根目录：

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

打开 `http://127.0.0.1:3080`，确认启动日志里有插件加载（命令 `/office-eval` 出现在斜杠菜单即可）。

## 用法

1. 在对话里发送 `/office-eval auto`。
2. 输入办公任务（例如选型简报、PPT、看板）。
3. 等待智能体完成回答。
4. 插件会再调用两次基座模型：
   - 只根据用户任务生成质量选择题和固定位置事实检查点（此时不看回答）；
   - 用同一套蓝图检查刚才的回答。
5. 会话里出现一条可展开的评测通知；完整 Markdown 写到工作区的 `office-eval-results/`。

其它命令：

| 命令 | 作用 |
|---|---|
| `/office-eval` | 立即评测本会话上一轮已完成的用户任务 |
| `/office-eval auto` | 开启自动评测 |
| `/office-eval off` | 关闭自动评测 |
| `/office-eval status` | 查看是否已开启 |

把 `scratch-plugin/cordis.yml` 里的 `auto: true` 设上后，新会话默认开启自动评测。

## 评测口径

与评测文档一致：

- 每个回答单独评价；
- 选择题 + 固定位置事实抽查（A–G），不用 100 分制；
- 正确性、功能、视觉分层记录，互不抵消；
- 报告含每道题和每个检查点的选项、依据与抽查画像（如 `A×5、B×2、E×1`）；
- 虚构来源、抽查为 F、关键结果只能标 E 等情况会标「需要人工复核」。

评测调用使用该会话刚刚用过的 `provider` / `model`，但把 `reasoningEffort` 固定为 `off`：出题和打分需要可见 JSON，思考模式经常只产出 `reasoning` 块、没有 `text`，会话里就会出现「评测模型没有返回文本」。调用不经过 agent loop，因此不会再开一轮「让模型自己改答案」。通知会进入会话日志，下一次对话请求能看见评测摘要；若要做互不影响的对比，请每个候选用新会话。

## JSON 容错

评测模型有时会输出不合法的 JSON（最常见的是数组元素之间漏逗号）。插件做了三层兜底：

1. **自动修复**：解析失败时先用内置修复器处理常见错误（元素间补逗号、去尾随逗号、字符串内转义原始换行、单引号转双引号），修复后能解析就直接继续；
2. **自动重试**：仍失败时，把解析错误与失败位置附近的输出片段回喂给评测模型，要求重新输出合法 JSON，最多重试 `jsonRetries` 次（默认 2，可在 `cordis.yml` 配置，0 表示关闭）；
3. **可诊断报错**：最终失败时，错误信息会附带失败位置附近的输出片段，方便定位具体问题。

## 文件

| 文件 | 职责 |
|---|---|
| `src/office-eval-plugin.ts` | 命令、自动评测开关、idle 后触发 |
| `src/office-eval-pipeline.ts` | 抽取轮次、两次模型调用、JSON 修复/重试、写报告 |
| `src/office-eval-prompts.ts` | 出题与评分提示词 |
| `src/office-eval-json.spec.ts` | JSON 修复与解析的单元测试 |

```sh
pnpm vitest run --config scratch-plugin/vitest.config.ts
```
